# 加密笔记（二开功能）

加密笔记需要用户主动选用，普通笔记不受影响。正文会先在客户端加密再保存，所以服务端、备份和同步拿到的始终是密文。在新建笔记菜单里选择“加密笔记”即可创建。

## 实现方式

- 加密在 Web/桌面客户端里用 WebCrypto 完成。
  - 密钥由口令经 PBKDF2-SHA256 派生，迭代 600,000 次，每篇笔记单独加盐。
  - 正文用 AES-256-GCM 加密，每次保存都使用新的 IV。
  - 口令和派生出的密钥只放在内存里。空闲 15 分钟或手动锁定后会清除。
- 存储沿用现有字段，不需要新增 Migration。
  - `content_markdown` 存放一行占位文字和 `<!-- edgeever-encrypted-v1:… -->` 密文信封。
  - `content_json` 和 `content_text` 只有占位文字“🔒 Encrypted note”。搜索、摘要、AI 和 MCP 看到的只有这一行。
- 所有加密笔记共用一个保险库口令。
  - 每台设备在本地存储里保存一个小的加密校验值，新建笔记时用它发现口令输错。
  - 这个校验值只在本机，不会同步。

## 刻意保留的限制

- **口令丢失**：忘记口令后笔记无法恢复，也没有重置方式。
- **标题**：标题、标签和所在笔记本都保持明文。
- **附件**：不能插入图片或文件，因为附件上传时不会加密。
- **不可用的功能**：正文搜索、AI 与 Companion、MCP 读写正文、公开分享和笔记本分享、合并都不支持。
- **单向**：不能把加密笔记原地解密回普通笔记。需要转换时，把内容复制到一篇新笔记。
- **已有笔记**：明文笔记不会被原地加密。要保护已有内容，先新建加密笔记并粘贴进去，再删除原笔记并清空回收站。在此之前生成的历史版本、备份和数据库快照仍然保留明文。

## 服务端拦截与部署

本 fork 构建的服务端会：
- 拒绝任何会丢掉密文信封的写入（409 `encrypted_update_required`），历史版本恢复也包括在内；
- 拒绝合并和分享加密笔记；
- 只向 MCP 返回占位内容；
- 在 `/api/v1/auth/session` 中声明 `features.encryptedNotes`。

客户端只有在服务端声明了这项能力时，才会提供加密笔记。

上游 Android、iOS 应用不认识这种格式，只会显示占位文字。用户在那里编辑后，fork 服务端会把这次保存当作冲突拒绝，而不会覆盖密文。**上游**服务端镜像没有这道拦截，不要在上游服务端上使用加密笔记。

- 加解密往返、口令错误、篡改和参数边界；
- 搜索与摘要只含占位文字；
- 拒绝丢弃信封的更新、只带 JSON 的更新和历史版本恢复；
- 拒绝合并，以及 MCP 返回内容的脱敏。

- 真实部署从上游镜像升级到本 fork；
