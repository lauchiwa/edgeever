# 加密笔记（二开功能）

加密笔记需要用户主动选用，普通笔记不受影响。正文会先在客户端加密再保存，所以服务端、备份和同步拿到的始终是密文。在新建笔记菜单里选择“加密笔记”即可创建。

## 实现方式

- 加密在 Web/桌面客户端里用 WebCrypto 完成。
  - 密钥由口令经 PBKDF2-SHA256 派生，迭代 600,000 次，每篇笔记单独加盐。
  - 正文用 AES-256-GCM 加密，每次保存都使用新的 IV。
  - 口令和派生出的密钥只放在内存里。空闲超时（默认 5 分钟，可在“设置 → 常规 → 加密内容”中选择 1、5、15 或 30 分钟，按设备保存，不会同步）或手动锁定后会清除。
- 存储沿用现有字段，不需要新增 Migration。
  - `content_markdown` 存放一行占位文字和 `<!-- edgeever-encrypted-v1:… -->` 密文信封。
  - `content_json` 和 `content_text` 只有占位文字“🔒 Encrypted note”。搜索、摘要、AI 和 MCP 看到的只有这一行。
- 所有加密笔记和加密块共用一个保险库口令。解锁其中任意一个后，在保险库锁定之前，打开其他加密内容都不需要再次输入口令。
  - 每台设备在本地存储里保存一个小的加密校验值，新建笔记时用它发现口令输错。
  - 这个校验值只在本机，不会同步。
- 锁定时不丢编辑，也不混用口令。
  - 锁定前会先用当前密钥保存打开的笔记，以及还没点“完成”的加密块草稿。无法保存的修改会被丢弃，并给出提示。
  - 在加密块草稿中输入同样算作活动。
  - 空闲时长按真实时间计算。电脑休眠或标签页在后台的时间同样计入；超时后窗口一回到前台就会立即锁定。
  - 退出登录、会话过期或切换账号时，保险库会锁定。
  - 用另一个口令解锁时，会先保存并锁定当前会话，再改用新口令。所以已打开的内容不会被新口令重新加密。

## 刻意保留的限制

- **口令丢失**：忘记口令后笔记无法恢复，也没有重置方式。
- **标题**：标题、标签和所在笔记本都保持明文。
- **附件**：不能插入图片或文件，因为附件上传时不会加密。
- **不可用的功能**：正文搜索、AI 与 Companion、MCP 读写正文、公开分享和笔记本分享、合并都不支持。
- **单向**：不能把加密笔记原地解密回普通笔记。需要转换时，把内容复制到一篇新笔记。
- **已有笔记**：明文笔记不会被原地加密。要保护已有内容，先新建加密笔记并粘贴进去，再删除原笔记并清空回收站。在此之前生成的历史版本、备份和数据库快照仍然保留明文。

## 服务端拦截与部署

本 fork 构建的服务端会：
- 拒绝任何会丢掉密文信封的写入（409 `encrypted_update_required`），历史版本恢复也包括在内；
- 拒绝合并和分享加密笔记；
- 拒绝给加密笔记上传图片或附件（409 `encrypted_note_unsupported`），包括单次上传、分片上传、MCP 和表格表单，因为附件以明文存储；
- 只向 MCP 返回占位内容，历史版本列表、恢复预览和修改结果也包括在内；
- 在 `/api/v1/auth/session` 中声明 `features.encryptedNotes`。

客户端只有在服务端声明了这项能力时，才会提供加密笔记。

本 fork 的 Android 测试版（见[二开版发布](fork-releases.zh-CN.md#android)）可以解锁并编辑已有的加密笔记：
- Hermes 没有 WebCrypto，所以由原生模块 `apps/mobile/modules/edgeever-crypto` 调用系统 `javax.crypto` 完成 PBKDF2 与 AES-GCM。同一份密文信封在 Web、桌面端和 Android 上都能打开。
- 口令和密钥只放在内存里。达到“设置 → 常规”中选择的空闲时长（默认 5 分钟，按设备保存）、手动锁定，或切换账号或服务器时会清除。
- 本地 SQLite 镜像和离线待发送队列里只有密文，本地搜索和摘要只看到占位文字，明文从不写入草稿。
- 加密笔记禁用富文本编辑器、AI 草稿、图片和附件。新建加密笔记仍需在 Web 或桌面端完成。

上游 Android、iOS 应用不认识这种格式，只会显示占位文字。用户在那里编辑后，fork 服务端会把这次保存当作冲突拒绝，而不会覆盖密文。**上游**服务端镜像没有这道拦截，不要在上游服务端上使用加密笔记。

## 行内加密块

普通笔记里也可以只加密一小段内容，比如部署记录里的账号密码。在编辑器里输入 `/secret`（或搜索“加密块”）即可插入，标签保持明文，只有密文内容被加密。

- 加密方式与加密笔记相同，并共用同一个保险库口令；附加数据（AAD）单独设置，所以加密块无法被当作加密笔记打开，反之亦然。
  - 同一篇笔记里的加密块共用一个盐，每次加密都使用新的 IV。单个加密块最多 32 KB，每篇笔记最多 100 个。
- 存储形式是 `edgeever-secret` 代码块，里面是一行 JSON（`id`、`label`、密文信封）。不认识这种格式的客户端会把它当作普通代码块保留，而不会丢弃或清空笔记。
- 明文只存在于加密块组件的内存状态里，不写入文档、草稿、离线队列或同步数据。锁定保险库后会立即清除。
- 编辑完成并点击“完成”后才重新加密，内容未改变时不会重新加密。
- 搜索、摘要、分享页面、AI、Companion 和 MCP 只看到“🔒 标签”。AI 划词改写不会覆盖包含加密块的选区。

服务端拦截：
- 未声明支持加密块的客户端（请求头 `X-EdgeEver-Client-Features` 中没有 `secret-blocks-v1`）保存时，每个原有加密块都必须原样保留在 JSON 和 Markdown 中，否则返回 409 `secret_block_update_required`。它们仍然可以修改加密块周围的文字或标签。
- 加密块数量超过上限时返回 400 `secret_block_limit`。
- 服务端在 `/api/v1/auth/session` 中声明 `features.secretBlocks`。客户端只有在服务端声明这项能力后，才提供插入命令并发送上述请求头。

限制：
- 标签和笔记其余内容都是明文。
- 包含加密块的笔记不能被 AI 或 MCP 整篇改写（会返回 409），但仍可以修改标题和标签。
- 历史版本恢复不经过这道拦截，但恢复前会先保存当前版本，所以仍可找回。
- 本 fork 的 Android 测试版以标签显示加密块，并以只读方式打开：点按加密块会弹出原生对话框，输入保险库口令（同一保险库会话只需一次）后即可查看或复制内容。明文只保留在该对话框中，关闭对话框、保险库锁定或应用切到后台时即被清除，不会进入编辑器 WebView、笔记或本地存储。编辑或新增加密块需要使用 Web 或桌面端；删除或改动加密块的保存会被服务端拒绝。

## 验证情况

自动化测试覆盖：
- 加解密往返、口令错误、篡改和参数边界；
- 搜索与摘要只含占位文字；
- 拒绝丢弃信封的更新、只带 JSON 的更新和历史版本恢复；
- 拒绝合并，以及 MCP 返回内容的脱敏；
- Android 加密核心与 WebCrypto 的双向互通（在桌面 JVM 上），以及 Android 保险库、自动保存的重新加载规则和本地占位文字。

已手工验证：
- 在浏览器中连接 fork 服务端（v1.120.0-rc.1）解锁加密笔记；
- 本 fork 签名的 Android 测试版（1.120.0，`714a494`）在真机上：解锁并阅读其他客户端创建的加密笔记，在 Android 上编辑后能同步到其他客户端，闲置 15 分钟后自动锁定，插入图片和附件已禁用，且不出现上游更新提示；
- 行内加密块：Windows 桌面端与本 fork 签名的 Android 测试版（均为 v1.122.0-rc.2，`9d59be3`）连接 fork 服务端，Android 在真机上：在 Windows 上插入加密块，同步后在 Android 上显示标签，用保险库口令解锁，口令错误时给出提示，复制内容，同一保险库会话内打开其他加密块无需再次输入口令，在 Android 上编辑笔记的其余部分后，所有加密块在 Windows 上仍完整且可以解开。

尚未验证：
- Windows 桌面端完整链路；
- 真实部署从上游镜像升级到本 fork；
- 上游移动端在真机上的实际表现；
- 可配置的自动锁定时长在 Windows 和 Android 真机上的表现；
- Android 上有一次编辑带加密块的笔记后一直停在“保存中”，重启应用后恢复。之后未再出现（包括连接 logcat 时），原因未明。
